# Subsystem name

Copy this template when adding a subsystem. This file is a documentation
template, not an implementation or a completed subsystem report.

## Purpose

State the responsibility, non-goals, and dependencies.

## Public interfaces

List actual APIs/formats/commands with caller obligations, ownership, error
behavior, and stability. Say "none implemented" if only proposals exist.

## Invariants

State conditions that must remain true and how violations are detected.

## Implementation status

Separate implemented (with evidence), planned, and experimental items.

## Tests

Give exact commands, assertions, expected failure cases, and coverage limits.

## Known limitations

Record unsupported cases, unresolved decisions, and bootstrap dependencies.
