# RynorLang Stage 19d — conformance, determinism, self-host checklist (frozen specification)

Status: **frozen.** Executable spec for Stage 19d: the canonical
encoding of the full language, the bounded type/rule/cap pairing
matrix, host determinism evidence (3× byte-identical), the guest
boundary, the `--profile=strict` mechanism, the 19e seed plan, and
the kLOC budget counting rule. Nothing here executes by itself.

Precedence: below all earlier frozen contracts; above the implementation.

## 1. Scope

IN: canonical encoding spec for every frozen construct (type
strings, value bytes/layouts, print bytes, key bytes + hash,
AST-JSON order, RIR text, symbol numbering, asm-text contract);
a bounded conformance matrix crossing types × rules × caps with
±1 boundary pairs; host 3× byte-identical evidence over the full
19a–19c corpus (text artifacts ungated, linked/run artifacts
toolchain-gated with recorded evidence); the guest boundary (what
runs where, full parity owned by 19e); `--profile=strict` flag
plumbing with two frozen rules (R1/R2 below); the seed plan as a
document; the kLOC counting rule + counter (reference measurement
only); a banned-nondeterminism-source pin.
OUT: full-language guest execution (19e owns guest execution with
19e's tests); the narrower core-dialect subset (19e defines
`dialect="core"` against its baby-compiler capabilities — mechanism
here, subset there); the baby compiler itself; any semantic change
to frozen constructs; RNG/fuzzing (enumeration only, no random
case generation — generated bytes must themselves be deterministic).

## 2. Canonical encoding (host; pins existing behavior)

- Type strings: `agtypes.canonical` output is the canonical form
  (scalars `int`/`bool`/`str`/`status`, nominal stored names,
  `generic` with `<...>` args and integer caps). Byte-exact.
- Value bytes: records in declaration order, inline, padding-free;
  lists as length + capacity slots inline; maps in slot order with
  FNV-1a64 key bytes; `status`/`result` as tag + payload with
  zeroed err payloads. Layout sizes from `record_sizes` (static).
- Print bytes: existing frozen render (decl-order records,
  slot-order maps, `true`/`false`, strings raw). Byte-exact.
- Key bytes + hash: `agtypes` key encoding + FNV-1a64 (oracle
  re-derives identically).
- AST JSON: `sort_keys` with sorted value lists (existing
  `iter_ast_json`); byte-identical to `json.dumps(sort_keys=True)`.
- RIR text: `rir.dumps` format (ordered strtab/rectypes/funcs/
  blocks/instrs) is byte-deterministic for identical input; the
  header echoes the caller-supplied filename spelling (callers pin
  theirs; the corpus uses `<project>/main.rl` and bare names).
- Symbol numbering: source order `0..n-1` for functions, records
  follow; merged programs follow merge order (entry-first DFS)
  with running offsets (existing `_merge_order`).
- Asm text: `compile.emit_asm` output is deterministic text
  (existing contract); linked bytes are toolchain-determined and
  covered by gated evidence, not by byte pins.
- Manifests: comparison is order-insensitive parsed JSON;
  byte-canonical form (sorted keys) is recommended, not required
  (hashes cover file bytes, never manifest bytes).
- Pipeline purity: no RNG, clock, environment, or filesystem
  enumeration reaches any artifact. Pinned by a banned-import test
  (RFC §8): `random`, `time`, `datetime`, `os.urandom`,
  `os.listdir` stay absent from `tools/rynorlang` (allowlist:
  `os.environ` toolchain override, `os.name` runner branch,
  `os.fork/dup2/execv/waitpid` inside *generated* child code only).

## 3. Conformance matrix (bounded; enumerated, no RNG)

Dimensions (frozen list; each cell is accept or exact-code reject):
- Types: `int`, `bool`, `str`, `status`, `result<int,E>`,
  `record`, `list<T,N>`, `map<K,V,N>` (+ `unit` where rules touch it).
- Rules: exact-type equality, `==` per identical-type pair, print
  per type, `len`/index/push per aggregate, `match` per scrutinee
  (status/result/int/bool/str) × arm shape (ok/err/lit/wild/bind),
  exhaustiveness/reachability, shadowing (param/let/match-bind vs
  functions), first-error order, qualification (`alias::R` type,
  construction, call), mangling, pin/edition/cycle/load order.
- Caps (each with accept/reject ±1 where the bound is numeric):
  `MAX_SOURCE_BYTES` (1 MiB), `MAX_STR_LEN` (4096),
  `MAX_DEPTH`/`PARSE_MAX_DEPTH` (256), `MAX_AGG_BYTES` (8192),
  `MAX_TYPE_NESTING` (8), `MAX_FRAMESLOTS` (1024),
  `MAX_USES_PER_FILE` (64), `MAX_IMPORT_DEPTH` (16),
  `MAX_MODULES` (64), `MAX_MANIFEST_BYTES` (64 KiB),
  `MAX_ALIAS_LEN` (64), oracle budgets (`STEP_LIMIT`/`CALL_LIMIT`).
  Match-arm COUNT carries no numeric cap (only shapes: empty
  rejected, single, multi; nesting bounded by `MAX_DEPTH`).
Bound: the matrix is an enumerated case list in the test file
(each case names its cell); new fixture files ≤ 64, each ≤ 60
lines. Cells already covered by 19a–19c suites are referenced,
not duplicated (the matrix test asserts the enumeration covers
every cell of §3 exactly once — inventory over the pairing set).

## 4. Determinism evidence

- Text artifacts (lex→parse→analyze→RIR→asm text): 3×
  byte-identical over the FULL 19a–19c corpus (aggregates +
  control + modules projects, manifests included), UNGATED
  (no toolchain needed) — required.
- Linked/run artifacts (obj/exe/stdout/exit): 3× byte-identical,
  toolchain-gated (nasm+ld absent on some dev machines), with
  sha256 evidence recorded in the stage report — required where
  the toolchain exists.
- Guest: the only guest language execution is the frozen 18d
  evaluator (`rleval`/`rlen`: int/bool/str subset). 19d evidence:
  those suites green + their session transcripts byte-identical
  across 3 runs. Full-language guest execution is 19e's exit
  (19e's tests); 19d documents the boundary (this section).
- Rationale for the split: text artifacts prove the language
  pipeline deterministic everywhere; linked bytes additionally
  depend on the host toolchain (out of contract); guest parity
  needs an execution environment 19e builds.

## 5. `--profile=strict` (mechanism frozen; subset handoff to 19e)

- Flag: `--profile default|strict` on the analyze and program
  CLIs (default = current behavior, byte-identical). Library
  entry points (`Analyzer`, `analyze_entry`, `build_program`,
  `build_module_program`) take `profile="default"` with the same
  default. Unknown values are CLI usage errors (exit 2, argparse).
- R1 (edition lock): under `strict`, shell-edition constructs are
  rejected even when the edition flag says shell
  (`SEM_PROFILE_EXCLUDED`, new additive code). v1 inputs are
  unaffected (they never contain shell constructs).
- R2 (reproducible multi-file): under `strict`, any `use`
  without a present, fully-pinning manifest is rejected
  (`MOD_PIN_MISMATCH`, message notes the strict profile).
  Single-file programs are unaffected.
- Handoff: the narrower 19e-writable core subset is NOT defined
  here (guessing it without the baby compiler is forbidden);
  19e adds its subset with its own RFC + matrix (15b precedent),
  reusing this flag (e.g. a `core` value) and this section's
  test hooks. `strict` as frozen here stays valid forever.

## 6. Seed plan (document; binds 19e procedure, not 19d code)

1. Host builds the 19e compiler sources (`.rl`, core subset)
   with the frozen host pipeline (`--profile=strict`); record
   input hashes + asm text hashes.
2. The resulting binary is NOT directly executable (Linux ELF
   target); the seed step cross-checks semantics via the oracle
   on the 19d conformance corpus: oracle-vs-native equality for
   every executable cell.
3. First self-build runs on RynorOS once 19e provides guest
   execution; comparison is byte-level on RIR text + asm text
   (toolchain bytes excluded per §4).
4. Instructions + expected hashes live with the 19e RFC; 19d
   freezes only this procedure and the corpus it runs on.

## 7. kLOC budget (counting rule frozen; harness now, gate in 19e)

- Counting rule: non-blank, non-comment (`//` full-line) lines
  in the 19e compiler's `.rl` sources (manifest + std excluded
  from the count; vendored std counted separately and also
  budgeted). Counter: `tools/rynorlang/kloc.py` (stdlib only,
  deterministic, tested).
- Budget stays ~1.5 kLOC (existing prose). 19d records the
  reference measurement of the host pipeline (informational,
  not a gate — different language, different artifact).
- 19e wires the gate (counter + CI threshold with its RFC).

## 8. Diagnostics (additive; frozen codes untouched)

- `SEM_PROFILE_EXCLUDED` (R1: strict-profile construct).
- R2 reuses `MOD_PIN_MISMATCH` (unpinned import; strict noted
  in the message). First-error order preserved (profile checks
  ride their existing phases: R1 at edition/analysis, R2 at
  manifest load).

## 9. Alternatives considered

- B1 full type×rule×cap cross-product as generated files:
  rejected — unbounded fixture sprawl; the enumerated matrix
  with referenced (not duplicated) cells covers every pairing
  with a fixed file budget.
- B2 RNG-seeded conformance generation: rejected — generated
  bytes must be deterministic; enumeration is reviewable, RNG
  output is not (and a seed is just an opaque number).
- B3 requiring nasm/ld everywhere (no skips): rejected — dev
  machines without the toolchain must still run the suite;
  text-artifact 3× is ungated, linked evidence is recorded.
- B4 guest execution for the full language in 19d: rejected —
  no execution environment exists (18d evaluator covers
  int/bool/str only); 19e builds it with 19e's tests. The
  boundary is documented, not wished over.
- B5 defining the core-dialect subset now: rejected — the
  subset must match the baby compiler's capabilities, which
  don't exist yet; freezing a guess would bind 19e to fiction.
  Mechanism now, subset in 19e (explicit handoff, §5).
- B6 strict = warnings instead of errors: rejected — a lock
  that doesn't lock is commentary; violations are errors with
  codes like every other contract in this language.
- B7 hashing manifest bytes: rejected — hashes cover file
  bytes (the integrity target); manifest form stays
  order-insensitive by design (§2).

## 10. Critics (strongest objection each, all resolved)

1. Kernel correctness: N/A (host-side only; guest suites
   untouched except re-recorded evidence).
2. Language semantics: "R2 (manifests required under strict)
   breaks unpinned-mode programs." → Resolved: only under the
   explicit flag (default unchanged); reproducible builds need
   pinned inputs — that IS the point of strict. Locked.
3. ABI/compat: "a new SEM_ code grows the contract." →
   Resolved: additive-only (previously-valid v1 inputs never
   trigger it; shell-under-strict was never valid). Locked.
4. Scope honesty: "ROADMAP says core-dialect lock, but §5
   punts the subset." → Resolved: the lock MECHANISM (flag,
   plumbing, codes, hooks) is the freezable unit; the subset
   needs the baby compiler to exist. ROADMAP row updated to
   record the handoff explicitly. Locked.
5. Minimalism: "the matrix re-tests settled stages." →
   Resolved: cells reference existing fixtures (no
   duplication); the matrix adds only uncovered pairings +
   the coverage-inventory test. Locked.
6. Testability: "text 3× without execution proves little."
   → Resolved: execution equality is already proven per
   suite (differentials); 19d adds corpus-wide text 3×
   (ungated) + linked 3× evidence (gated) + guest
   transcripts. Three independent layers. Locked.
7. Cold reviewer: "canonical encoding just describes code."
   → Resolved: description WITH byte-pins and a banned-source
   test turns accident into contract; mutants prove each pin
   loads-bearing. Locked.
